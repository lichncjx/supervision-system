# 导入导出规则

## 一、基本原则

> 导入导出权限原则详见 [业务规则](../core/业务规则.md) §一-9。

当前实现：

1. 普通导出接口为 `GET /api/excel/export`，数据范围与 `GET /api/works` 可见范围一致；年度、工作事项、部门、状态、关键词和月份必须与触发导出的事项列表当前筛选一致。
2. 普通导入接口为 `POST /api/excel/import/[type]`，默认创建 `DRAFT`，状态流转仍必须通过 workflow。
3. completionRate 导出已在前面阶段按主责部门口径处理，本阶段重点是普通事项导入导出。
4. `src/lib/excel-utils.ts` 仍被模板下载和部分前端工具函数引用，暂作为 legacy 工具保留；普通导出以服务端接口为准，后续可单独清理未使用的客户端导入导出函数。

## 二、重点工作和主要工作字段

> 责任字段规则详见 [业务规则](../core/业务规则.md) §一-3。

导入时不强制匹配 `User` 或 `Member`；导出时按事项记录中的姓名输出。

重点工作和主要工作模板中的“工作事项”“工作节点”分别对应结构化字段 `workItem`、`workNode`，两列均为必填。导入记录一行就是一个可独立审批、调整和考核的工作节点；系统不通过标题文本拆分字段。

## 三、年度与预览确认

1. 年度不写入 Excel 列，由用户在导入预览时选择；确认导入时年度与文件均不可变更。
2. 导入必须先由服务端解析并返回行级预览、错误与重复节点提醒。存在错误时不能确认导入。
3. 确认导入使用服务端签发的短时预览令牌，并校验当前用户、导入类型、年度和 Excel SHA-256 一致；服务端随后重新解析、校验权限/人员/字段并在一个事务内写入。
4. 模板中仅事项级列的真实 Excel 单列合并单元格可以向下继承其左上角值：重点工作支持“工作事项”“业务类别”“是否为创新工作”，主要工作支持“工作事项”“业务类别”。普通空白单元格绝不继承上一行；整行空白跳过，部分空白按缺少必填字段报错。
5. 同一工作事项下工作节点相同会在预览阶段提醒，不默认阻止导入；单次导入最多 200 行。

## 四、待办事项字段

> 责任字段规则详见 [业务规则](../core/业务规则.md) §一-4。

主责部门规则（Phase 8B）：导入时所有事项类型统一使用 `departmentId` + `responsibleLeader` + `responsiblePerson` + `cooperators`。

## 五、状态导入导出

### 普通导入

1. 普通业务导入默认创建 `DRAFT`。
2. 导入后由系统用户通过 workflow 提交。
3. 导入不直接写入 `currentApproverId` / `currentApproverRole`。
4. 导入不直接写入 `beforeApprovalStatus` / `approvalType`。

### 历史迁移导入

> 旧状态到新状态映射详见 [业务规则](../core/业务规则.md) §二-1。

## 六、导出展示

1. 状态文案使用统一状态元数据 `getWorkStatusLabel`。
2. 所有事项类型统一导出：主责部门、责任领导、责任人、配合方。
3. 配合方格式为 `部门|领导|人员；部门|领导|人员`（例如 `工艺技术处|王主任|赵工；质量管理处|刘主任|钱工`）。
4. 导出不暴露密码、token、内部审计字段、审批记录、附件、证明材料、节点 JSON 等详情页字段。
5. 如需导出审批记录，应作为单独明细表或单独功能，不混入普通事项清单。

## 七、导入权限

1. `ADMIN` / `SUPERVISOR` 可按全局范围导入。
2. `DEPARTMENT_LEADER` / `DEPARTMENT_MANAGER` 只能导入主责部门包含本部门的事项；配合部门可以填写其他部门，但不能替代主责部门授权。
3. `VICE_PRESIDENT` / `PRESIDENT` 不默认获得全局导入权限；普通导入仅允许导入本人提出或本人审批的待办事项。
4. 责任领导、责任人、主责责任人、配合责任人只作为姓名文本导入，不校验系统用户，不产生权限。

## 八、导入字段兼容（Phase 8C）

1. 所有事项类型统一使用单一主责部门 `departmentId`。
2. 配合方使用结构化文本格式：`部门|领导|人员；部门|领导|人员`，导入时解析为 `cooperators` JSON。
3. `responsibleDepartmentIds`、`cooperateDepartmentIds`、`responsiblePersons`、`cooperatePersons` 已删除。
4. `responsibleLeader` 和 `responsiblePerson` 为姓名文本字段，所有类型统一使用。

## 九、已接受风险

1. 责任人姓名可能重名。
2. 人员调岗后历史姓名不会自动关联新部门。
3. 无法按人员 ID 精确统计个人责任事项。
4. 无法基于责任人姓名做系统通知和权限控制。
5. 如后续确有人员维度统计、通知、权限控制需求，再评估 `DepartmentMember` / `WorkParticipant`。
# PR 6.3 当前补充

1. 当前普通导入默认 `DRAFT`，状态列仅允许空、`DRAFT` 或“草稿”。
2. 普通导入不允许写入 `PROPOSING`、`ADJUSTING`、`CANCELLING`、`COMPLETING`、`IN_PROGRESS`、`COMPLETED`、`CANCELLED`，也不接受旧状态值。
3. 普通导出状态文案只来自 9 状态元数据；状态筛选不再接受旧状态值。
4. `APPROVED` 已取消，进行中只使用 `IN_PROGRESS`；完成审批统一为 `COMPLETING`；取消审批统一为 `CANCELLING`。
5. `src/lib/excel-utils.ts` 继续作为模板和 legacy 客户端工具保留，后续 PR 6.4 可单独清理未使用路径。
